# Document Normalizer 规格

## 目标

把拍照/扫描得到的试卷源图归一化成稳定的扫描 PDF，再交给题目识别、答案识别和批改流程。

这一层只处理纸面几何问题，不做 OCR、不做题目划分、不做判题。

## V1 流程

1. 前端读取试卷源文件原图。
2. 前端通过 `document-normalizer` 抽象调用 Scanic 检测纸面四角。
3. 前端显示可拖拽四角编辑器，用户复核或修正角点。
4. 前端提交归一化角点坐标，坐标范围为 0–1。
5. 后端把归一化角点转换成原图像素坐标。
6. 后端使用现有 OpenCV homography 透视校正，并生成新的扫描 PDF。
7. 后端保存：
   - 原始文件引用；
   - 当前扫描后文件引用；
   - 预处理状态；
   - 质量分；
   - 分割/透视/警告元数据。

## 非目标

- 不硬编码某张卷子的角点、题号或页数。
- 不在这一层修题目识别 prompt。
- 不在这一层做标准答案生成或批改。
- 不用局部旋转/仿射替代完整四角透视校正。

## 抽象边界

前端业务代码不直接绑定具体扫描库，而是通过：

- `detectDocumentWithScanic`
- `createDocumentCornerEditor`
- `preprocessExamDocumentWithQuads`

后续可把 Scanic 替换或扩展为：

- OpenCV.js baseline；
- jscanify fallback；
- 自研多候选四边形评分；
- 后端曲面展开服务。

## 质量门控

V1 使用后端已有 `preprocessing_status`、`preprocessing_quality`、`preprocessing_metadata` 展示结果。

后续应增加：

- 四角置信度；
- 文本水平度；
- 内容贴边检查；
- 页面截断检查；
- 双页/单页分类；
- 每阶段耗时：原图读取、角点检测、人工确认、后端透视、PDF 生成。

## 成功标准

对同一张学生卷子：

1. 不依赖硬编码坐标；
2. 复核四角后分割预览可稳定显示完整页；
3. 题目识别只消费归一化后的扫描结果；
4. 新算法结果必须和参考源码输出做题块覆盖率、文字准确率、置信度、耗时对比。
