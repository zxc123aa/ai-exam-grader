# 点凡阅卷生产运行手册

## 生产基线

- Web/API 至少 2 个实例，worker 至少 2 个实例；数据库使用 RDS PostgreSQL 高可用版，Redis 使用主从高可用版。
- 文件放在私有 OSS Bucket，禁止公共读；应用通过 KMS 注入访问凭证，不写入镜像、仓库或前端环境变量。
- API 使用 `/api/v1/utils/health/live` 做存活检查，使用 `/api/v1/utils/health/ready` 做流量就绪检查。
- Adminer 仅保留在本地 override，生产 Compose 不发布数据库管理入口。
- 每 5 分钟执行 `python -m app.maintenance reconcile-billing`，释放异常退出遗留的额度预占。
- 每分钟执行 `python -m app.maintenance dispatch-outbox`，异步发送履约通知并同步财务系统。

## 上线流程

1. CI 必须通过后构建不可变镜像，以提交 SHA 标记。
2. 先在 staging 执行 `alembic upgrade head`，完成上传、生成答案、批改、复核、发布的冒烟测试。
3. 生产采用 expand-contract 数据库迁移：先增加兼容字段/表，应用全部升级后再移除旧结构。
4. 先发布一个 canary 实例，观察错误率、P95 延迟、队列积压和模型成本 15 分钟，再全量。
5. 回滚只切回上一镜像；如果迁移不可逆，必须在发布前提供恢复脚本和演练记录。

## 商业运营闭环

- 平台超管或平台管理员从「平台管理 -> 订单与财务」维护年度套餐、答卷加量包、学校订单、发票和退款。
- 商品先建草稿、复核价格与额度后再上架；历史订单保存购买时的商品快照，下架或新版本不改变已购订单。
- 学校年度套餐续费从现有到期日顺延；加量包只允许服务期内购买。
- 微信支付回调必须验签、解密、核对订单金额并按事件 ID 去重；线下转账必须填写唯一银行流水号。
- 一张订单只允许一张发票申请和一笔退款申请；人工重试不会重复开通合同、发放额度或完成退款。
- 自动退款仅支持整单，且订单额度尚未预留或消费；续费退款后恢复仍有效的上一份合同。
- 每日核对支付流水、订单金额、合同、答卷额度与退款状态；不允许直接修改余额绕过订单和账本。

## 文件迁移到 OSS

1. 创建私有 Bucket，启用服务端加密、版本控制和生命周期规则。
2. 配置 `STORAGE_BACKEND=oss`、`OSS_ENDPOINT`、`OSS_BUCKET_NAME`、`OSS_ACCESS_KEY_ID`、`OSS_ACCESS_KEY_SECRET`。
3. 先运行：`python backend/scripts/migrate_storage_to_oss.py --source-dir data/uploads --dry-run`。
4. 核对 missing 为 0 后去掉 `--dry-run`；迁移是幂等覆盖，不删除本地文件。
5. 抽查 PDF、图片、题区裁切和历史答卷后，再停止本地卷挂载。

## 备份与恢复

- RDS 自动备份：每日全量、持续日志备份；目标 RPO 不超过 15 分钟，保留至少 35 天。
- OSS：开启版本控制和跨区域复制；误删文件先从历史版本恢复，不直接重传同名空对象。
- 每季度在隔离环境执行一次完整恢复演练，目标 RTO 不超过 4 小时，并记录恢复耗时和缺失项。
- 恢复顺序：新建隔离 RDS -> 时间点恢复 -> 校验迁移版本 -> 接入只读应用 -> 校验租户/账本/文件 -> 切换业务流量。
- 额度账本、支付回调、成绩发布记录属于高价值数据，恢复后必须做数量与金额对账。

## 告警建议

- 可用性：ready 失败 2 分钟、5xx 超过 1%、P95 超过 2 秒。
- 队列：最老任务等待超过 5 分钟、失败任务连续增长、worker 心跳丢失。
- 模型通道：单通道错误率超过 10%、所有备用通道不可用、费用突增超过近 7 日同期 3 倍。
- 商业风险：额度预占超过 30 分钟、负毛利订单、回调验签失败、同一学校分钟调用量异常。
- 数据：RDS 备份失败、OSS 跨区域复制延迟、恢复演练逾期。

## 故障处置

- 模型通道异常：禁用通道并观察自动路由；不要修改老师进行中的批次参数。
- Redis 异常：计费与并发保护故障关闭，暂停新批改；已完成结果仍可查看和复核。
- OSS 异常：ready 返回失败并停止接收流量，避免数据库记录与文件对象不一致。
- 支付回调异常：保留原始回调，验签和幂等处理恢复后重放，禁止人工直接改余额。
