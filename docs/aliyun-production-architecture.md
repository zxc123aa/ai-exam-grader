# 点凡阅卷阿里云生产架构

## 推荐拓扑

- 公网入口：阿里云 WAF -> 应用型负载均衡 ALB -> 两个以上 API 实例。
- 计算：SAE 部署 API 与 worker，分开扩缩容；API 根据请求量，worker 根据队列等待时间扩容。
- 数据：RDS PostgreSQL 高可用版、云数据库 Redis 主从版，全部放在同一 VPC 私网。
- 文件：私有 OSS；下载由 API 鉴权后返回短时签名 URL，第一阶段仍可通过 API 临时缓存兼容旧流程。
- 密钥：KMS/应用配置管理注入数据库、OSS、支付和模型中转凭证，不写入 `.env` 镜像层。
- 日志与指标：SLS 收集结构化日志，ARMS/APM 采集调用链、P95、错误率；SLS 告警发到企业微信值班群。

## 网络边界

- RDS、Redis、OSS 内网 endpoint 只允许应用安全组访问。
- 平台管理后台使用独立路径和更严格 WAF 规则；后续为平台管理员强制 MFA。
- 不开放 Adminer、数据库端口、Redis 端口和 Traefik 管理面板到公网。
- 模型中转出站使用固定 NAT EIP，便于供应商 IP 白名单和账单追踪。

## 容量起点（3–10 校试点）

- API：2 × 2 vCPU / 4 GiB，最少实例数 2。
- worker：2 × 4 vCPU / 8 GiB；模型并发由平台、学校、通道三层限流，不按机器线程盲目放大。
- RDS：2 vCPU / 8 GiB 起，开启 Performance Insight 和慢 SQL。
- Redis：1–2 GiB 主从版，禁止淘汰额度预占和并发锁相关 key。
- OSS：标准存储 + 版本控制；原卷与答卷按合同保留期配置生命周期。

## 扩容信号

- API P95 连续 10 分钟超过 1.5 秒或 CPU 超过 65%，横向扩容。
- 队列最老任务超过 3 分钟，先确认模型通道健康，再扩 worker；通道限额已满时扩机器无效。
- RDS CPU 超过 60%、连接超过 70% 或慢查询增长，先索引/查询治理，再升配。
- 单学校突发流量必须受学校并发、每分钟调用、每日额度和异常行为规则共同约束。
