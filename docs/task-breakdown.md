# 任务拆解

本文档将 `plan.md` 的开发周期拆成可执行 Epic。`plan.md` 是完整总纲，本文档用于日常推进和 issue 拆分。

## 里程碑概览

| 周期 | Epic | 建议时长 | 状态 |
| --- | --- | ---: | --- |
| 周期 0 | 项目初始化与技术底座 | 1 周 | 待开始 |
| 周期 1 | 人工试卷标定基础能力 | 2 周 | 待开始 |
| 周期 2 | AI 一键建立试卷模板 | 2-3 周 | 待开始 |
| 周期 3 | 学生答卷处理与模板配准 | 2 周 | 待开始 |
| 周期 4 | 客观题与基础 OCR 判分 | 2 周 | 待开始 |
| 周期 5 | 主观题和视觉大模型判分 | 3 周 | 待开始 |
| 周期 6 | 教师复核、批注回写与导出 | 2 周 | 待开始 |
| 周期 7 | 评测、试点和生产部署 | 2 周 | 待开始 |

## 周期 0：项目初始化与技术底座

目标：完成可运行的 Web 项目、后端、数据库、任务系统、文件存储和基础开发规范。

范围：
- 基于 Full Stack FastAPI Template 建立前后端 Monorepo。
- 保留用户登录、JWT、PostgreSQL、Docker Compose、测试和 CI 基础能力。
- 接入 Redis 与 Dramatiq，区分 CPU Worker 和 Model Worker。
- 定义坐标系统、文件目录规范、任务状态机和第三方许可证清单。

交付物：
- 可一键启动的 Web 项目。
- FastAPI 后端、React 前端、PostgreSQL、Redis、Worker。
- 登录页面、API 文档、开发规范、文件上传读取能力。

验收标准：
- 系统可以本地启动。
- 用户可以登录。
- 后端可以创建测试考试。
- Worker 可以执行测试任务。
- 文件可以上传和读取。

建议 issue：
- AEG-001 初始化 Full Stack FastAPI Template 技术底座。
- AEG-002 清理模板示例业务并建立项目命名。
- AEG-003 配置 PostgreSQL、Redis 和 Dramatiq。
- AEG-004 定义文件存储目录与坐标系统。
- AEG-005 定义核心数据模型草案。
- AEG-006 建立开发启动、测试、日志和错误处理规范。
- AEG-007 建立第三方许可证清单。

## 周期 1：人工试卷标定基础能力

目标：先保证不依赖 AI 时，教师也能手动建立完整试卷模板。

范围：
- 创建考试，上传空白试卷，支持 PDF、JPG、PNG。
- 将 PDF 渲染为页面图片。
- 用 React Konva 开发页面编辑器。
- 支持框选题目区域、答案区域、姓名、学号和页码区域。
- 支持设置题号、题型、满分、标准答案和评分点。
- 保存归一化坐标，支持模板保存、预览、修改、发布和版本管理。

交付物：
- 试卷上传页面。
- 页面预览。
- 人工模板编辑器。
- 题目配置表单。
- 模板保存和发布功能。

验收标准：
- 教师可以手动建立一套完整模板。
- 页面缩放后区域坐标不偏移。
- 模板关闭后重新打开可以完整恢复。
- 每道题可以设置答案和分值。
- 主观题可以设置评分点。

## 周期 2：AI 一键建立试卷模板

目标：上传试卷后自动生成模板草稿，教师只修正异常项。

范围：
- 接入 PaddleOCR，提取文字、题号、分值和坐标。
- 识别页面结构、大题小题层级、选项和答题区域。
- 解析标准答案和评分细则。
- 调用视觉大模型处理复杂版面。
- 生成带置信度的模板 JSON，并提供低置信度问题列表。

交付物：
- AI 一键标定按钮。
- 模板生成任务。
- 自动题目和答案区域。
- 置信度显示和教师纠错界面。

验收标准：
- AI 结果只能作为可编辑草稿。
- 低置信度项目必须教师确认。
- 教师可以修改所有 AI 结果。
- 修改后模板可以正常发布。

## 周期 3：学生答卷处理与模板配准

目标：实现学生答卷上传、页面矫正、模板配准和单题裁剪。

范围：
- 单份和批量上传。
- PDF 和图片渲染。
- 模糊、曝光、分辨率检测。
- 页面边缘检测、四角修正、透视矫正和旋转。
- 与空白模板配准，保存 Homography 和配准质量。
- 按模板裁剪答案，支持失败任务重试和人工修正。

验收标准：
- 倾斜拍摄页面可以矫正。
- 学生卷可以与模板对齐。
- 题目裁剪区域完整。
- 配准失败可以人工修正。

## 周期 4：客观题与基础 OCR 判分

目标：完成选择题、判断题、数字填空和短文本题的自动评分。

范围：
- OCR Worker 保存文字、坐标和置信度。
- 建立题型判分路由。
- 支持单选、多选、判断、标准答题卡、手写选项字母。
- 支持数值规范化、容差、单位规范化、短文本匹配和关键词匹配。
- 低置信度结果进入复核，自动生成基础勾叉和得分。

验收标准：
- 标准选择题可以自动判分。
- 数字答案能处理常见等价表达。
- OCR 原始结果可以查看。
- 判分结果不能超过题目满分。

## 周期 5：主观题和视觉大模型判分

目标：实现手写答案识别、评分点匹配和主观题建议评分。

范围：
- 建立统一 Vision Model Adapter。
- 发送匿名单题裁剪图给模型。
- 识别手写文本、简单公式和多行答案。
- 按评分点输出证据、扣分原因、建议得分和评语。
- 固定 JSON Schema，保存模型名称、版本、提示词版本和原始输出。
- 建立缓存和成本统计。

验收标准：
- 每个得分有相应证据。
- 模型不能自行更改满分。
- 输出格式错误不能进入最终成绩。
- 主观题默认进入教师确认。

## 周期 6：教师复核、批注回写与导出

目标：完成教师审核、卷面批注、PDF 导出和成绩统计。

范围：
- 教师复核工作台。
- 原卷和模型结果并排显示。
- 修改分数、评分点、扣分原因并保存修改原因。
- React Konva 批注图层，支持勾叉、圈选、下划线、扣分文字和总分。
- 后端渲染批注，导出 PDF、成绩表、每题得分和错题统计。

验收标准：
- 批注位置准确。
- 不同缩放比例下批注不偏移。
- 导出 PDF 与网页显示一致。
- 总分和各题得分计算正确。
- 每次人工修改均有记录。

## 周期 7：评测、试点和生产部署

目标：建立评测集，完成真实小规模试点并准备正式部署。

范围：
- 建立脱敏试卷测试集，覆盖清晰、模糊、倾斜、阴影和不同字迹。
- 评测页面配准、答案裁剪、OCR 和判分一致性。
- 统计人工复核率、严重误判率、耗时和模型成本。
- 优化阈值，完成权限、隐私、备份、日志和监控检查。
- 形成生产部署方案和下一版本需求清单。

验收标准：
- 完成一套试卷的完整批改。
- 页面配准达到可用水平。
- 客观题评分稳定。
- 主观题结果可解释。
- 异常题能进入人工审核。
