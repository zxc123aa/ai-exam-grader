# 点凡阅卷模型供应与计费运维手册

点凡阅卷只消费官方接口或已获授权的模型中转，不建设账号池，也不提供公开的 OpenAI 兼容转发端点。学校只购买点凡阅卷的订阅和积分，不能获得上游密钥或绕过业务流程直接调用模型。

## 权责边界

| 平台卖方 | 学校买方 | 普通老师 |
|---|---|---|
| 管理通道、密钥、真实模型、路由、成本、售价、合同、积分、风险状态和对账 | 选择点凡品牌处理方案，查看合同、积分和本校用量 | 上传试卷、生成参考答案、发起批改和人工复核 |

模型名、服务商、Token 和平台并发不进入普通老师界面。学校端只显示“点凡视觉标准”“点凡深度判分”等公开方案和积分。

## 生产配置

服务端必须配置：

```env
# python -c "import base64,secrets; print(base64.urlsafe_b64encode(secrets.token_bytes(32)).decode())"
PROVIDER_CREDENTIAL_MASTER_KEY=<Base64 编码的 32 字节随机密钥>
DYNAMIC_PROVIDER_ROUTING_ENABLED=true
BILLING_ENFORCEMENT_ENABLED=true
MODEL_MAX_OUTPUT_TOKENS=8192

# 仅当中转位于私网时配置；公网中转必须使用 HTTPS。
PROVIDER_PRIVATE_ENDPOINT_ALLOWLIST=relay.internal,10.20.0.0/16
```

主密钥只放在生产环境变量、Secret Manager 或 KMS，不进入 Git、数据库、镜像或前端。当前版本只有一个主密钥版本；轮换前需准备重新加密或重新录入全部通道密钥。

## 通道生命周期

- `草稿`：允许录入 URL、密钥、模型映射和成本，不参与生产流量。
- `启用`：允许被已发布路由选择。
- `排空`：不接新请求，正在执行的请求自然结束，适合维护或下线前切流。
- `禁用`：立即退出新请求路由；401/403 检测会自动进入此状态。

上线步骤：

1. 平台超管进入“平台管理 → 模型与中转 → 外部调用通道”。
2. 新建通道并录入 Base URL、API Key、协议、超时和通道并发。
3. 读取上游模型目录，添加“点凡标准模型名 → 上游模型名”映射。
4. 录入该通道真实的输入、输出、图片和缓存输入成本版本。
5. 执行模型检测；只有返回可解析结果且包含用量字段的映射才可进入生产路由。
6. 配置业务用途的主通道、备用通道和权重，保存为草稿版本。
7. 检查变更后发布路由版本；旧版本自动退役，可从历史版本重建新草稿回滚。
8. 创建学校可选方案和不可变售价版本，毛利低于 25% 时后端拒绝发布。

一个通道对应一个 Base URL 和一个 API Key。综合中转的一把 Key 可映射 Claude、Gemini、GPT 等多个模型；单模型 Key 只添加一条映射。

Sub2API、New API、CLI Proxy API 等只作为兼容上游类型，不代表点凡阅卷认可其账号来源。启用前必须确认授权、隐私、数据驻留和学校合同合规。OpenAI 没有“官方推荐 CPA”。

## 路由与故障处理

- 路由顺序：业务用途与标准模型 → 已发布版本 → 主/备用层级 → 同层稳定加权选择。
- 同一业务键粘滞到稳定通道，减少单个批次内结果波动；失败时按最大尝试数切换备用通道。
- `排空/禁用`通道不会通过旧环境变量旁路恢复。
- 连续 5 次网络或上游失败后熔断 2 分钟；成功请求不计入网络失败。
- 连续 3 次成功但缺少用量字段时，映射退出生产资格，需重新检测并发布路由。
- 重试或备用调用只要上游返回用量，即使结构化结果解析失败也计入真实成本和学校扣费。

## 积分、毛利与防刷

- 商业口径暂定 `1 积分 = 1 元`，变更口径必须创建新费率版本，不能修改历史记录。
- 默认目标毛利 40%，硬保护线 25%；售价按可能承接生产流量的最高成本校验。
- 每个任务创建前按近 30 天单次成本 P95 × 预计调用数 × 1.2 预留积分。
- 每次上游调用前再次授权；实际累计消耗接近预留时自动扩展，失败则暂停剩余调用。
- 所有成功尝试按上游返回用量结算，不允许用最初估价封顶真实扣费。
- 请求设置最大输出量，防止异常长输出把单次成本推到预留范围之外。
- PostgreSQL 负责积分预留和学校运行任务租约；Redis 负责每分钟调用数、学校/通道/平台模型并发。
- 生产计费开启时 Redis 故障关闭模型调用；本地演示关闭计费时可故障放行。
- 学校风险状态支持正常、限速观察、暂停新任务、冻结服务，并可设置每分钟调用、运行任务、模型并发、单任务、每日和每月积分上限。

## 对账

至少每日从上游导出请求明细，通过请求 ID、输入/输出量和成本导入通道对账。系统将每行标记为匹配、差异或上游缺失。运营人员需处理：

- 上游有账、点凡无记录：检查绕过网关、密钥泄露或记录失败。
- 点凡成功、上游无账：检查请求 ID、账单延迟或免费额度口径。
- 用量/成本不一致：确认缓存输入、图片计量、币种和费率生效时间。
- 单学校毛利跌破 25%、缺用量连续出现、401/403、异常重试率或日用量突增：立即排空通道或限制学校，复核后再恢复。

当前界面支持粘贴结构化对账行导入；正式运营接入各上游时，应增加定时拉账适配器和告警通知，但必须复用相同的不可变对账表，不另造一套账。

## 上线检查清单

- [ ] 生产数据库已迁移到 Alembic head，worker 与 API 使用同一版本。
- [ ] 生产密钥、数据库密码、超管密码均已替换默认值，代码仓库无密钥。
- [ ] 动态路由和计费强制均开启，Redis/PostgreSQL 有监控与备份。
- [ ] 每个已发布路由至少一个主通道和一个不同故障域的备用通道。
- [ ] 所有生产映射通过用量检测，通道成本和学校售价版本生效。
- [ ] 每所学校有有效合同、积分、用量策略和风险联系人。
- [ ] 告警覆盖 401/403、熔断、缺用量、余额不足、对账差异和毛利跌破保护线。
- [ ] 使用一所内部学校完成生成参考答案、批改、重试、积分耗尽、通道切换和对账演练。
