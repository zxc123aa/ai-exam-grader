# 点凡阅卷新服务器登录说明

更新时间：2026-08-03

## 快速登录

在 WSL 中执行：

```bash
cd /mnt/d/Songtan/ai-exam-grader/服务器部署
./ssh-new-server.sh
```

执行单条远程命令：

```bash
./ssh-new-server.sh 'hostname; uptime; docker ps'
```

脚本从同目录 `.env` 读取地址、用户、端口和密码。`.env` 已被项目根目录 `.gitignore` 忽略，不应提交。

该文件位于 Windows `D:` 盘，WSL/DrvFS 下 `stat` 可能固定显示为 `0777`，不能用这个数字判断真实访问权限。2026-07-27 已将其 NTFS ACL 收紧为仅当前 Windows 用户、`SYSTEM` 和本机管理员可访问。可在 WSL 中复核：

```bash
icacls.exe "$(wslpath -w .env)"
git check-ignore -v .env
```

## 2026-08-03 恢复记录

此前公网 `22` 在 SSH banner 阶段关闭或超时。经旧服务器跳板登录确认，根因是持续密码爆破使未认证连接挤满 sshd `MaxStartups`；不是 root 密码错误。

已完成：

- 安装并启用 fail2ban，`sshd` jail 使用 systemd 日志。
- 10 分钟内失败 5 次即封禁，初始封禁 1 小时并递增。
- UFW 撤销公网 `22/tcp`，将 `22022/tcp` 设置为 `LIMIT IN`。
- 从当前 WSL 环境直连 `22022` 验证成功。

维护检查：

```bash
systemctl status ssh fail2ban --no-pager
fail2ban-client status sshd
ufw status verbose
ss -lntp | grep ':22022'
```

不要重新开放公网 `22`，也不要在未检查日志的情况下清空防火墙规则或关闭安全服务。

## 点凡阅卷部署注意事项

- 项目根目录：`/mnt/d/Songtan/ai-exam-grader`
- 建议远端目录：`/opt/dianfan-grading`（尚未创建或确认）
- 生产运行手册：`../docs/production-operations.md`
- 主 Compose：`../compose.yml`
- `../compose.override.yml` 仅用于本地开发，生产命令必须显式排除它。
- 现有服务器的 `80/443` 已被 Nginx 占用。部署前先决定由现有 Nginx 反向代理，还是另设内部端口；不要直接启动会抢占端口的本地 Traefik。
- OCR GPU profile 需要 NVIDIA GPU；该 RackNerd VPS 未确认有 GPU，默认不要启用 `ocr-gpu` profile。
- 生产 `.env` 必须在服务器上单独生成强随机密钥，不能复制仓库开发 `.env`。

## Staging 部署入口

点凡阅卷试运行使用独立 Compose 文件，不读取本地开发 override：

```bash
./服务器部署/generate-staging-env.sh
./服务器部署/deploy-staging.sh <release-sha> config
./服务器部署/deploy-staging.sh <release-sha> infra
./服务器部署/deploy-staging.sh <release-sha> build
./服务器部署/deploy-staging.sh <release-sha> app
```

远端固定目录为 `/opt/dianfan-grading`，共享数据在 `shared/`，发布源码在
`releases/<release-sha>/`，`current` 只指向当前发布。应用数据库、Redis、上传目录、
容器网络和镜像均使用 `dianfan-staging` 前缀，不复用 AISubAPI 的数据库或 Redis。

公网入口使用 `app.dianfandig.com`。Nginx 配置模板位于本目录 `nginx/`：证书签发前
只启用 HTTP ACME 模板，签发后再切换 HTTPS 模板。

## 公开注册启用

公开注册默认关闭。正式启用前必须在 Cloudflare Turnstile 为
`app.dianfandig.com` 创建站点，并在服务器 staging 环境文件中配置：

```dotenv
SMTP_HOST=<SMTP 主机>
SMTP_USER=<SMTP 用户>
SMTP_PASSWORD=<SMTP 密码>
EMAILS_FROM_EMAIL=<发件邮箱>
TURNSTILE_SECRET_KEY=<Turnstile secret key>
VITE_TURNSTILE_SITE_KEY=<Turnstile site key>
PUBLIC_SIGNUP_TRIAL_RATE_VERSION=2026-demo-v1
PUBLIC_SIGNUP_ENABLED=true
```

`VITE_TURNSTILE_SITE_KEY` 是前端构建参数，修改后必须重新执行 `build` 和 `app`，
只重启容器不会生效。部署后依次验证注册页、人机验证、验证邮件、学校 ID、30 天合同
和 200 份答卷额度；任一环节异常时先把 `PUBLIC_SIGNUP_ENABLED` 改回 `false` 并重新发布
前端，已有学校登录与批卷不受影响。

## 安全和回滚

- 不输出或提交 `.env` 内容。
- 不复制旧服务器数据库或 volume，除非用户明确要求迁移。
- 操作已有容器、网络、Nginx 配置前先备份。
- 部署使用独立 Compose project 名，避免接管现有 AISubAPI 容器。
- 每次发布记录镜像 ID、迁移版本、回滚命令和健康检查结果。
