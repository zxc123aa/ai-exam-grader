## 第一步：生成 SSH 密钥

### Windows PowerShell

```powershell
ssh-keygen -t ed25519 -C "你的姓名或工作邮箱"
type $env:USERPROFILE\.ssh\id_ed25519.pub
```

### macOS 或 Linux

```bash
ssh-keygen -t ed25519 -C "你的姓名或工作邮箱"
cat ~/.ssh/id_ed25519.pub
```

使用默认保存位置即可。可以为私钥设置密码，提高本地密钥安全性。

生成后会得到两个文件：

- `id_ed25519.pub`：公钥，可以发送给服务器管理员。
- `id_ed25519`：私钥，只能由本人保管，禁止通过微信、邮件或网盘发送。

请将完整的 `.pub` 公钥文本发给服务器管理员。管理员配置完成并确认账号已创建后，再进行登录。

## 第二步：登录服务器

```bash

```

如果密钥没有保存在默认位置，可明确指定私钥：

```bash
ssh -i ~/.ssh/id_ed25519 -p 22022 dianfan-ops@155.94.192.143
```

Windows PowerShell 示例：

```powershell
ssh -i $env:USERPROFILE\.ssh\id_ed25519 -p 22022 dianfan-ops@155.94.192.143
```

## 操作边界

- 不得使用或索要 root 共享密码。
- 不得复制、查看或发送服务器上的 `.env`、API Key、数据库密码和支付凭据。
- 未经负责人确认，不得删除容器、镜像、volume、数据库、Redis 数据或上传文件。
- 未经负责人确认，不得运行 `docker compose down -v`、清库、重置防火墙或开放公网数据库端口。
- 部署前必须确认回滚版本，并在部署后检查 backend、worker、frontend 健康状态。
- PostgreSQL、Redis 和内部服务不得暴露到公网。
- 发现异常时先保留日志和现场，不要直接清理数据。

## 常见问题

### `Permission denied (publickey)`

通常表示管理员尚未添加公钥、登录账号错误，或 SSH 使用了错误的私钥。请将以下命令输出发给管理员排查：

```bash
ssh -v -p 22022 dianfan-ops@155.94.192.143
```

发送日志前应检查其中是否包含本地用户名、目录等不希望公开的信息。

### `Connection timed out` 或 `Connection refused`

先确认端口是 `22022`，不是默认端口 `22`。如果仍无法连接，请将当前公网 IP 和报错时间发给管理员检查防火墙、fail2ban 和 SSH 服务状态。

### 主机指纹发生变化

不要直接删除 `known_hosts` 后继续连接。服务器重装、SSH 主机密钥更换或中间人攻击都可能导致指纹变化，应先让管理员核验新的指纹。
