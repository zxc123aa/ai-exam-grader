# 试卷图片识别系统需求分析（第一版）

## 1. 目标

将手机拍摄的中学试卷图片自动整理为“题目 + 考生回答”的可校订数据。系统不承担自动判分，优先保证题目块完整、手写内容不丢失、跨页题目可追溯，并记录每个阶段的耗时。

## 2. 输入与输出

- 输入：一组 JPG/PNG/WebP 试卷图片。照片可能横竖混排、旋转、包含双页、书脊和透视变形。
- 识别中间产物：每张图的旋转角、物理页/栏目、题目块归一化坐标、阅读顺序、跨页续题关系。
- 结果：每题的题号、完整题干/选项、考生手写回答、题型、置信度、备注、来源块和 OCR 耗时。
- 导出：JSON（适合二次处理）和 Markdown（人工阅览）。任务元数据保存在 `data/jobs`。

## 3. 核心流程

1. 浏览器导入图片并生成缩略图。
2. 方向模型比较 0/90/180/270 四张实际候选图，选择文字真正正向的一张，避免顺/逆时针语义混淆。
3. 布局模型只在转正图片上分析题目块；一个块必须包含真实题号、完整题干、全部选项、插图和手写回答，不把标题或姓名栏当题目。
4. 浏览器使用与模型相同的转正坐标系显示红框并裁切，裁块额外保留少量安全边缘。
5. OCR 调度优先把同一考生、同一页且阅读顺序相邻的题块组成多图请求，由模型在一个 JSON 中逐块返回；结果仍按原始块独立落字段。批量响应映射不完整时自动降级为逐块识别，印刷题目和手写回答分别落字段，无法辨认处明确标记。
6. 对 `continuationOf` 相同的块按阅读顺序合并，跨页题目可形成一个结果；仍保留原始块列表。
7. 前端按考生分组、按题号排序展示，并自动标记重复题号、缺题、低置信度及不完整内容；人工修订后保存和导出。

## 4. 跨页规则

系统不假设图片文件名顺序就是阅读顺序。布局结果中的 `readingOrder` 和 `continuationOf` 是唯一依据：若题目从左页底部延续到右页顶部，两个块用相同的续题键合并；若模型无法确定，保留为两个块并在备注中提示人工确认，不静默拼接。

## 5. 非功能要求

- API Key 只在服务端 `.env`，前端不可见；模型调用使用 OpenAI-compatible `/v1/chat/completions`。
- OCR 默认 8 路并发、每请求最多 3 个相邻题块；单批格式异常自动降级，单块失败不影响其它块，并在结果中记录错误。
- 所有阶段记录毫秒耗时：布局、单块 OCR、总任务。
- 同一任务结果可重复打开和导出；原图不写入任务 JSON，避免结果文件膨胀。
- 题目和回答编辑区默认完整展开，不使用内部滚动条隐藏选项或长答案。

## 6. 当前版本边界

本版不自动判分、不做学生身份跨任务匹配、不提供后台常驻文件夹监听。图片导入采用文件选择/拖拽，后续可以在此基础上增加指定目录监听、批量学生归档和答案评分。
